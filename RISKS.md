# Risk Register & Mitigation Strategy

| Risk ID | Category | Risk Description | Probability | Impact | Mitigation Strategy | Status / Spike Finding | Owner |
|---|---|---|---|---|---|---|---|
| **RSK-001** | Technical / Perf | **Software WebGL & CSS Rasterization Bottleneck**: Complex WebGL or heavy CSS blurs (`backdrop-filter`) run slow on CPU without GPU, driving up server render time. | Medium | High | **Empirical Finding**: Three.js WebGL rendered at **5.7 FPS** (~176ms/frame). However, CSS `backdrop-filter: blur(16px)` dropped to **1.1 FPS** (~924ms/frame). Mitigation: Pre-flight linter flags heavy CSS blurs; client-side WebCodecs offloads compute to user device. | Mitigated / Verified | Full-Stack Lead |
| **RSK-002** | Technical / Audio | **Audio-Video Desynchronization**: Frame-stepping decouples execution time from real-time audio playback, causing audio drift or missing sound in `<audio>` / `<video>` / Web Audio. | Low | Critical | **Empirical Finding**: Dual-track interception (OfflineAudioContext + direct media track extraction + FFmpeg mux) achieved **100% sync** across all 3 audio formats with zero audio drift. | Closed / Verified | Lead Engineer |
| **RSK-003** | Security | **Untrusted Code Execution / Sandbox Escape**: Users upload arbitrary HTML/JS containing SSRF attacks, crypto miners, or local filesystem access. | Medium | Critical | Multi-layer sandbox: Chromium CDP network interception blocks RFC 1918 private IPs (`10.0.0.0/8`, `127.0.0.0/8`, `169.254.0.0/16`, `192.168.0.0/16`), hard execution time limits (e.g. 90s), memory limits (2GB), ephemeral container isolation, auto-deletion of uploaded files immediately after processing. | In Progress (Sprint 2) | Security Lead |
| **RSK-004** | Technical / Quality | **Non-Deterministic Code in Uploaded HTML**: Code relying on unseeded `Math.random()`, external CDN scripts that fail to load, or variable network conditions renders inconsistently. | High | Medium | Pre-flight linter (Sprint 1) detecting unseeded PRNGs, live network dependencies, and un-hooked intervals, generating copy-paste AI prompt fixes for users. | Planned (Sprint 1) | Lead Engineer |
| **RSK-005** | Financial / Infra | **Runaway Cloud Infrastructure Costs**: Free-tier users rendering heavy Three.js 1080p clips exhaust serverless/VPS compute budgets. | Low | High | **Empirical Finding**: Client-side WebCodecs costs **$0.0000/min**. Dedicated VPS worker costs **$0.0015 - $0.0068/min**. Client-side first strategy eliminates server burn for free tier. | Mitigated / Verified | CTO |
| **RSK-006** | Compliance / Store | **Chrome Web Store MV3 Review Delay / Rejection**: Extension requesting broad permissions or executing dynamic code blocked by Web Store review. | Medium | High | Strict Manifest V3 compliance: zero remote script execution, minimal host permissions, pure client-side WebCodecs / Offscreen Canvas pipeline. | Planned (Sprint 3/4) | Full-Stack Lead |
| **RSK-007** | Technical / Engine | **Asynchronous ESM Script Initialization**: `<script type="module">` executes asynchronously after initial document load, causing early frame capture before animation is ready. | Medium | Medium | **Empirical Finding**: Sample 4/5 ESM scripts initialized after page load. Mitigation: Engine must inject an initialization handshake (`window.__RENDER_READY__ = true`) or await module execution before capturing frame 0. | Closed (Sprint 1 Spec) | Lead Engineer |
| **RSK-008** | Technical / Engine | **GSAP paused: true / Custom Hook Freeze**: Animations initialized with `paused: true` or custom timeline runners do not advance with `requestAnimationFrame` alone, causing all captured frames to be identical. | High | Critical | **Empirical Finding**: User's 46s Reel froze at frame 0 because GSAP timeline was paused. Mitigation: Engine now explicitly invokes `window.seek(t)`, `window.renderFrame(idx, t)`, and `gsap.globalTimeline.time(t)` on every tick. | Closed / Verified | Full-Stack Lead |
| **RSK-009** | Reliability | **SSE Socket Disconnect / EPIPE Server Crash**: Client browser refreshes or disconnects during long rendering jobs threw unhandled stream write errors, terminating the Node.js server. | Medium | High | **Empirical Finding**: Resolved with active SSE heartbeat pings (every 4s), socket writable checks (`res.writableEnded`), stream drain listeners, and global uncaughtException traps. | Closed / Verified | Lead Engineer |
